# 玩家反馈分析助手 V3.0.9

一个单文件、可直接打开的玩家反馈整理工具。导入访谈摘录、问卷开放题或社区评论后，可逐条核对原话，提取具体体验问题，归并同类问题，并生成带来源依据的报告草稿。

**建议 GitHub 仓库名：`game-player-feedback-assistant`。**这是游戏玩家反馈分析作品，与周报类仓库 `weekly-report-skill` 是两个不同项目。

## 立即使用

直接打开 [`index.html`](index.html) 即可使用，无须安装依赖或配置模型密钥。也可以把本文件夹中的 `index.html` 和 `README.md` 上传到 GitHub 仓库根目录；如需网页访问，可将该仓库设为 GitHub Pages 的发布源。

首次使用建议按页面中的顺序操作：

1. 新建反馈批次，填写游戏与版本，导入反馈材料。CSV/TSV 表格按行拆为独立反馈；纯文本可选择按行或空行拆分。导入预览会显示识别数量。
2. 下载分析任务，把任务文本交给你选择的 AI 对话工具，再将返回的 JSON 结果回填。页面不会自动调用模型。
3. 逐条核对问题与原话；遗漏可补录，错误可修改。人工修改会保留标记和修改记录。
4. 在“归并与核查安排”中按业务大类查找具体问题、调整分类和核查安排，再生成报告。桃源深处有人家批次提供活动、剧情、种田经营等候选大类，分类可人工更改。

材料和问题列表支持搜索及分页。具体问题可直接打开对应反馈；一条反馈包含多个问题时，多个问题共用该条来源。对旧版误将整张表导为一条反馈的材料，可预览后逐条拆分。草稿可保留未核对标记；正式报告需要完成页面提示的核对条件。

## 数据与使用边界

- 这是浏览器内运行的单人版本。反馈、人工判断和报告保存在**当前网站地址对应的浏览器本地存储**，不会随仓库代码上传到 GitHub，也不会在不同网址间自动同步。
- 从原来的本地文件地址改用 GitHub Pages 时，先在旧页面点击“导出备份”，再在新地址点击“恢复备份”。备份可能包含玩家原话和用户标识，请自行妥善保管，**不要提交到公开仓库**。
- 使用外部 AI 对话工具分析时，任务文本会包含你选择导出的原话。是否发送及发送给谁由使用者决定。
- 本版没有多人登录与权限隔离，也没有服务端存储。浏览器存储容量有限，大规模长期使用（尤其上万条反馈）需要服务端或其他持久化方案。
- 真实玩家游玩经历仅按文本和已有标识给出候选判断，不能据此证明已经实际游玩；问题优先级由人判断。
